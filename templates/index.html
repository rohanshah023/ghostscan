      How GhostScan finds hidden malware in documents

      Five steps, from the moment you add a file to the report you read. The file is only ever read as data. It is never opened, shown or run.

      1

      Receive the file or link

      You upload a document or paste a link. GhostScan accepts PDF, Word, Excel and PowerPoint files, older .doc and .xls files, ZIP, RTF, text and images.

      • The file is held in memory and handled as a block of bytes.
      • Nothing is opened in Word, a PDF viewer or a browser, so nothing can run.
      • A link is scored from its text alone (for example a raw IP address, a look-alike domain, a direct .exe download). It is not visited unless downloading is switched on.
      2

      Check it is safe to look at

      Before any analysis, GhostScan checks that the file is what it claims to be.

      • Extension and size: only supported types are accepted, with a size limit.
      • Real type: the first bytes (the magic bytes) show the true format, such as %PDF- for PDF or PK for Word and Excel files.
      • Disguises: a mismatch (an .exe named .pdf), a double extension such as invoice.pdf.exe, or hidden direction characters in the name raise the score.
      • Fingerprints: SHA-256, SHA-1 and MD5 hashes are calculated, so the exact file can be compared with known threats.
      • Isolation: analysis runs in a separate process with a CPU limit, a memory limit, no permission to write files, and a time-out. A booby-trapped file can only crash that process.
      3

      Look inside the document (static analysis)

      This is where hidden content is found. Each format is opened as data and examined in its own way.

      PDF files

      • The raw bytes are searched for risky keywords: /JavaScript, /OpenAction, /Launch, /EmbeddedFile, /RichMedia, /XFA, /SubmitForm and links.
      • Names written with hex codes (like /J#61vaScript) are flagged, because they are used to hide keywords.
      • Compressed streams are safely inflated, then searched for exploit-style script calls such as app.alert, eval and unescape.
      • Data after the final end marker, and the author, creator and dates are recorded.
      3

      Word, Excel and PowerPoint

      Modern Office files are ZIP archives of small parts. GhostScan looks at the archive and then at each part.

      • The archive: a huge expansion ratio (a zip bomb), paths that escape the folder, password-protected entries, and programs or scripts packed inside.
      • Macros: a vbaProject.bin file, auto-run names such as AutoOpen, and calls like Shell, CreateObject or URLDownloadToFile.
      • Remote content: external links, a remote template that loads when the file opens, and DDE fields that can run commands without a macro.
      • Embedded items: ActiveX controls and embedded objects.
      • Hidden text: zero-width and direction-control characters in the document text.
      • Older .doc and .xls files are searched for macro streams in the same way.

      For every file type, GhostScan also searches for known attack patterns (PowerShell download commands, embedded Windows programs, command-line tricks), compares the hash with a list of known threats, and measures entropy, which highlights packed or encrypted blocks.

      4

      Score the evidence

      Every finding has a weight from 0 to 100. A rule such as "contains a macro project" is weighted by how often that signal means trouble.

      • Weights are combined as risk = 1 - (1 - w1)(1 - w2)..., so several weak signals add up, one strong signal dominates, and the score never passes 100.
      • Dangerous combinations get a small extra boost, such as active content together with a disguised file or an external link.
      • A hash that matches a known threat scores 100.
      • Verdicts: under 10 is Clean, 10 to 34 Low risk, 35 to 69 Suspicious, and 70 or more Malicious.
      5

      Read the report

      You get the result in plain language, with the reasons behind it.

      • The risk score and verdict.
      • The evidence: each finding, its weight, its category and what was found.
      • The file properties and metadata: hashes, real type, size, author, dates and links.
      • An entropy chart showing which sections look packed or encrypted.
      • Next steps that match the verdict, such as not opening the file, isolating it, or checking with the sender.

      What to keep in mind

      • A macro, a link or invisible text is not automatically malicious. Many real documents have them, which is why GhostScan shows evidence and a score instead of a yes or no.
      • Static analysis cannot prove a file is safe. It can miss new or well-hidden threats, so for important files also use an up-to-date antivirus.
      • Encrypted or password-protected content cannot be inspected, and GhostScan flags it instead.
